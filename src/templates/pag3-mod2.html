Como o juiz da OBI mede o tempo de execução

O tempo de execução depende do algoritmo e do volume de dados. Mesmo um código correto pode falhar se for muito lento para os limites do problema.

Complexidade de tempo e limites do problema

A OBI usa um limite de tempo para cada tarefa, por exemplo 1 a 3 segundos. O código é executado em um servidor com entrada de teste completa e se ultrapassar o limite, o resultado é Tempo Excedido.

  • O(n): geralmente aceito para entradas com até 10^7 operações simples;
  • O(n log n): aceitável para n até cerca de 10^5 ou 10^6 em muitas tarefas;
  • O(n^2): só funciona para n pequeno, como 10^3 ou menos;
  • O(2^n) / O(n!): só serve para n mínimo, tipicamente n ≤ 20 ou menos.

Para saber se seu código será aceito, compare a complexidade do seu algoritmo com o tamanho máximo de entrada informado no enunciado.

Quando o juiz diz "Tempo Excedido"

O resultado de tempo excedido aparece quando o programa não termina dentro do tempo limite usando o caso de teste mais pesado. Isso ocorre mesmo que o código esteja correto para casos menores.

  1. Algoritmo muito lento para a entrada máxima;
  2. Laços aninhados que causam muitas operações;
  3. Uso excessivo de ordenação, buscas lineares ou conversões dentro de loops;
  4. Leitura ou escrita lenta repetida para grandes volumes de dados.

Por exemplo, um algoritmo O(n^2) com n = 10000 faria 100 milhões de operações, o que costuma ser lento demais para o tempo de competição.

Quando o código é aceito

Um código é aceito quando produz o resultado correto para todos os testes dentro do limite de tempo e memória. A eficiência importa tanto quanto a exatidão.

  • Use o algoritmo correto para o tamanho da entrada;
  • Evite repetir trabalho desnecessário em loops;
  • Prefira operações lineares ou n log n quando possível;
  • Leia dados rapidamente com `sys.stdin.readline()` ou `sys.stdin.read()` para muitos valores.

Exemplo típico aceito: processar 200.000 números em O(n) lê-los, somar e imprimir o resultado sem loops extras caros.

Exemplos de código e análise de tempo

Compare duas abordagens para o mesmo problema: dado um conjunto de números, verificar se existe um par cuja soma é 100. A primeira solução é lenta (O(n^2)) e tende a dar "Tempo Excedido" em entradas grandes; a segunda é eficiente (O(n)). 

# Lento: O(n^2) - pode dar Tempo Excedido
n = int(input())
valores = list(map(int, input().split()))
for i in range(n):
    for j in range(n):
        if valores[i] + valores[j] == 100:
            print("SIM")
            break

Essa solução testa todos os pares, o que cresce muito rápido. Para grandes n, ela geralmente é rejeitada. 

# Eficiente: O(n) - normalmente aceito
import sys

n = int(sys.stdin.readline())
valores = list(map(int, sys.stdin.readline().split()))
seen = set()
for x in valores:
    if 100 - x in seen:
        print("SIM")
        break
    seen.add(x)
else:
    print("NAO")

Dicas para não levar Tempo Excedido

  • Entenda o enunciado e o limite de entrada antes de codar;
  • Avalie a complexidade esperada: O(n), O(n log n) ou O(n^2)?;
  • Use estruturas rápidas como `set`, `dict`, `list` e `deque` de forma adequada;
  • Evite ordenar quando não for necessário;
  • Prefira ler a entrada inteira e processar em memória quando o volume for grande.
